# UVT — Universal Voice Translator

**Начать здесь:** [простая инструкция запуска](README_START.md) — интерфейс, все три режима и запуск двойным щелчком на Mac.

**Перевод речи для видео и системного звука: локальный, бесплатный или облачный — с понятным маршрутом данных.**

UVT сознательно разделяет два разных сценария. Это важно для ожиданий от скорости и синхронности:

| Сценарий | Команда / интерфейс | Что происходит на самом деле | Когда выбирать |
| --- | --- | --- | --- |
| 🎬 **Пакетный дубляж** | `uvt dub`, браузерная кнопка, вкладка Batch в GUI | Сначала обрабатывается весь файл/ролик, затем собирается готовая дорожка по таймкодам | Нужны качество, субтитры и точное положение реплик в видео |
| 🎧 **Live перевод** | `uvt run`, вкладка Live в GUI | Фраза заканчивается → STT → перевод → TTS → воспроизведение с целевой задержкой | Звонки, плееры, стримы, игры; голос появится после исходной фразы |

Браузерная кнопка **не является live-переводом**: она запускает batch-задачу на локальном сервере. Но ждать всю дорожку не нужно — каждая озвученная реплика публикуется сразу и звучит в видео по своему таймкоду, пока остальные ещё считаются. Live не может заранее подготовить неизвестную следующую фразу, поэтому не обещает липсинк или мгновенную замену голоса.

## Локальная студия для M4 / 16 ГБ

После `uvt serve-personal` откройте [Файлы и переводы](http://127.0.0.1:8765/workspace). Здесь можно выбрать скачанное видео или аудио, отправить ссылку, следить за этапами, отменить задачу и скачать M4A, SRT, VTT, TXT, JSON. Для загруженного видео доступен MKV с переведённой и исходной дорожками: видеоряд копируется без перекодирования. Файловый результат содержит приглушённый оригинал под переводом; userscript получает отдельный голос для синхронизации с плеером.

Загрузка ограничена 2 ГБ и 90 минутами, поскольку полная звуковая дорожка пока собирается в памяти. Загруженный исходник удаляется после окончания/отмены; результаты хранятся в кэше, список задач действует до перезапуска сервера. Ссылки на результат защищены токеном конкретной задачи, если настроен `UVT_API_TOKEN`. Кнопки облачных маршрутов сохраняют их исходное назначение — для обработки без провайдеров выбирайте локальный профиль.

Рекомендации и первоисточники моделей: [LOCAL_MODELS_M4.md](docs/LOCAL_MODELS_M4.md). Реальный замер на этом Mac: [BENCHMARK.md](artifacts/benchmark/BENCHMARK.md). Состояние реализации и дальнейшие шаги: [TODO_LOCAL_M4.md](TODO_LOCAL_M4.md).

Для звонков добавлен `local-meeting`: локальные субтитры Parakeet → TranslateGemma без TTS. Сначала настройте захват BlackHole/виртуального устройства и выберите его в профиле; `uvt devices` показывает устройства. `uvt gui -p local-meeting` открывает GUI с субтитрами, `uvt run -p local-meeting` — консоль. Это экспериментальный захват аудиовхода, а не встроенная интеграция WebRTC; реальная задержка звонка ещё не измерена.

При ошибке `Unsupported URL` UVT теперь проверяет явно объявленные ссылки HTML5/Playerjs-плеера. Текущий `video.currentSrc` имеет приоритет над сетевыми ресурсами рекламы. На macOS обычный запуск автоматически проверяет FFmpeg и при известной ошибке x265 подключает уже установленную библиотеку нужной ABI только для процесса UVT. Если подходящей библиотеки нет, выводится отдельная ошибка установки FFmpeg.

## Что умеет UVT

- **Пакетная синхронизация:** распознавание с пословными таймкодами, пофразовая раскладка TTS и ускорение слишком длинных реплик. В готовом экспорте сохраняются реальные границы TTS, а не оценка по длине текста.
- **Честный Live-путь:** единые часы захвата, target/deadline для реплики, newest-first обработка и счётчики намеренно пропущенных фраз. GUI показывает p50 задержек, drift и drops, когда они доступны движку.
- **Маршруты данных на выбор:** private local, free без платных API, Cloud Fast и Cloud Quality — без ложной надписи «offline» для Edge TTS.
- **Независимые движки:** Parakeet/Whisper/облачные STT, TranslateGemma/NLLB/OpenAI-совместимый перевод, Edge/OpenAI/Piper/Kokoro TTS, plugins и ленивые зависимости.
- **Субтитры и история:** оверлей, SRT/VTT/TXT/JSON, исходный текст и перевод.
- **Один desktop-интерфейс:** отдельные вкладки Live и Batch, выбор входа/выхода, подсказки BlackHole/WASAPI/PipeWire, статус каждой стадии и видимая ошибка.

## Быстрый старт

Нужны Python 3.10+ и `ffmpeg` (`brew install ffmpeg` / `apt install ffmpeg`).

```bash
git clone <ваш-репозиторий> uvt && cd uvt        # скачать репозиторий и перейти в него
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[recommended,server,web]"
uvt run -p demo                 # smoke test без моделей и сети
uvt profiles                    # список честных маршрутов данных
```

Дополнительно:

```bash
pip install -e ".[gui]"        # desktop-интерфейс
pip install -e ".[piper]"      # локальная озвучка Piper для -p local
pip install -e ".[mlx]"        # Apple Silicon: локальный Whisper на Metal
pip install -e ".[mac-local,server,web]"  # M1/M2/M3/M4: весь private-local batch-маршрут
uvt setup-mac-local --preset balanced  # M4/16 ГБ: pinned Parakeet, TranslateGemma и RU/UK Piper
uvt setup-mac-local --preset balanced --check  # offline-проверка без скачивания
# Либо --preset all, если нужен выбор Fast/Balanced/Quality в браузере
uvt serve-personal
# Web-панель статуса и настроек: http://127.0.0.1:8765/
# Локально открыть её при старте: uvt serve-personal --open-browser
```

## Команды

`uvt profiles` держит этот список в актуальном виде в терминале.

| Команда | Что делает | Полезные флаги |
| --- | --- | --- |
| `uvt run -p <профиль>` | Live-конвейер в консоли (системный звук → перевод) | `--source-lang`, `--target-lang`, `--mode {subtitles,voiceover}`, `--debug` |
| `uvt dub <файл\|ссылка> -p <профиль>` | Пакетный дубляж: готовая дорожка + `.srt`/`.json` | `--output/-o`, `--duck-db`, `--no-original-track`, `--debug` |
| `uvt serve -p <профиль>` | Сервер для браузерной кнопки (userscript) | `--host`, `--port`, `--target-lang`, `--source-lang` |
| `uvt serve-personal` | Одновременно Local/Free, GPT и ElevenLabs + web-панель | `--open-browser` (только local desktop), `--free-profile`, порты |
| `uvt gui -p <профиль>` | Desktop-интерфейс: вкладки Live и Batch | `--debug`; профиль можно сменить прямо в окне |
| `uvt devices` | Список аудиоустройств, виртуальные помечены `🔁` | — |
| `uvt profiles` | Готовые профили и их маршрут данных | — |
| `uvt setup-mac-local` | Скачать или offline-проверить закреплённые локальные модели Apple Silicon | `--preset {fast,balanced,quality,all}`, `--check` |
| `uvt version` | Версия установленного UVT | — |

`-p/--profile` принимает как имя файла из [profiles/](profiles/) (`cloud-fast`, `local`, …), так и путь к своему YAML. Примеры:

```bash
uvt gui -p cloud-fast                      # desktop-интерфейс на облачном быстром маршруте
uvt gui -p local                           # тот же интерфейс, но private local (нужны настроенные модели)
uvt run -p cloud-fast --target-lang en     # live-перевод в консоли, целевой язык — английский
uvt dub ролик.mp4 -p cloud-quality -o ролик.ru.mkv  # пакетный дубляж файла в указанный путь
uvt serve -p free --port 8080              # сервер для браузерной кнопки на порту 8080
```

### Резерв cloud-профилей

`cloud`, `cloud-fast`, `cloud-eleven` и `cloud-quality` при ошибке или отказе OpenAI лениво
переключают STT на локальный Whisper, а перевод — на локальный Ollama с
`qwen2.5:3b`. Для этого резерва заранее должны быть доступны модель Whisper,
запущенный Ollama и модель Qwen; до ошибки облака они не загружаются в память.
Выбранный OpenAI или ElevenLabs TTS остаётся облачным компонентом.

`cloud` сохранён как совместимое имя `cloud-fast`. Он больше не означает «локальный Whisper + облачный только перевод»: в cloud-профилях активный STT и TTS также могут быть облачными.

### Что значит «local» на практике

Новые `local-fast`, `local-balanced` и `local-quality` не отправляют аудио или
текст наружу **во время работы** и запрещают скачивание весов внутри задачи.
Единственная точка загрузки — явная команда `uvt setup-mac-local` с immutable
ревизиями. При старте сервер без сети проверяет кэш и голоса, загружает первый
STT в Metal и показывает `model_readiness` в `/meta`; переводчик включается
только после освобождения STT, чтобы не раздувать unified memory.

Для Piper положите рядом с выбранной `voice.onnx` её исходный metadata-файл
`voice.onnx.json`. UVT берёт `audio.sample_rate` только из этого локального
sidecar и остановится при отсутствии, повреждённом JSON или несовпадении со
старой явной настройкой `tts.sample_rate`: иначе сырой PCM мог бы прозвучать с
неверным темпом и высотой голоса.

`free` означает «без оплаты токенов», а не «без сети»: Edge TTS бесплатен без ключа, но передаёт текст сервису Microsoft. Аналогично, `google-free` — сетевой неофициальный endpoint, а не private fallback.

### Оптимальный локальный маршрут для Mac M4 с 16 ГБ

```bash
source .venv/bin/activate
pip install -e ".[mac-local,server,web]"
uvt setup-mac-local --preset balanced  # только при первой установке
uvt setup-mac-local --preset balanced --check  # последующая offline-проверка
uvt serve-personal              # поднимет Local, GPT и ElevenLabs вместе
```

На Apple Silicon команда `serve-personal` сама выбирает `local-balanced` для
первой кнопки. Parakeet распознаёт 25 европейских языков, включая EN/RU/UK, с
таймкодами и прогрессом по 60–120-секундным чанкам. После STT его MLX-модель и
кэш освобождаются, TranslateGemma переводит независимые реплики через свой
официальный structured template, затем Piper озвучивает RU/UK. Отмена ждёт
завершения только уже активного ограниченного STT/Piper-чанка и не оставляет worker в
фоне. `local-fast` быстрее, но NLLB переводит более буквально;
`local-quality` оставлен для сложного звука и использует chunked Whisper.
Готовый набор Piper включает мужской и женский голос для русского и
украинского; для другого целевого языка добавьте соответствующую Piper-модель
в `tts.voice_models` или выберите GPT/ElevenLabs.

### Перевод звучит по мере готовности

Озвученная реплика готова окончательно: она уже уложена в свой тайминг, и
менять её больше не нужно. Поэтому дубляж не ждёт конца обработки — сервер
публикует каждую реплику сразу, а браузер планирует её по таймкоду.

- `render_dub_track(..., on_clip=...)` вызывает подписчика, как только реплика
  озвучена и уложена в слот;
- сервер сохраняет её отдельным файлом и добавляет в статус задачи
  (`clips` в `/job/<id>`): положение в видео, длительность, текст, говорящий;
- userscript загружает реплики и проигрывает их через Web Audio по времени
  видео — с учётом паузы, перемотки и скорости, без наложения реплик;
- по завершении задачи браузер переключается на цельную дорожку: она надёжнее
  при перемотке в произвольное место.

На кнопке это видно как `слышно 12 · 40%`. Первые клипы появляются после распознавания и перевода исходника. Скорость зависит от длительности записи, профиля и прогрева моделей: на этом M4 повторная обработка 13,97 с записи в `local-balanced` заняла 20,13 с, первый клип — 19,06 с. Поэтому перед просмотром иногда нужно накопить готовый перевод; эти замеры не подтверждают работу быстрее реального времени.

### Живые голоса и интонации: маршрут `local-natural`

```bash
pip install -e ".[natural,server,web]"
uvt setup-mac-local --preset natural     # Parakeet + Qwen3 4B + F5-TTS RU
uvt dub ролик.mp4 -p local-natural
```

Профиль решает то, что `local-balanced` решить не мог: там голос фиксирован
моделью Piper, одна интонация на весь ролик, а укладка в тайминги делалась
ускорением готового звука (`atempo`) — на слух это перемотка. Здесь четыре
отличия.

**Голос берётся из самого ролика.** Для каждого говорящего выбирается самый
чистый фрагмент его речи (по громкости, длительности и доле паузы), и F5-TTS
синтезирует перевод этим тембром. Никаких «Дмитрия» и «Ирины» на всех.

**Реплика синтезируется сразу в свой тайминг.** F5 — flow-matching модель: она
генерирует речь заданной длины, поэтому доступный слот передаётся модели, а не
исправляется ускорением после. Замер: слот 3.0 с → 3.14 с, слот 2.2 с → 2.34 с.
Сильнее чем в `tts.max_compression` (по умолчанию 1.25) раз речь не ускоряется —
остаток выходит за слот, и следующая реплика сдвигается: это слышно лучше
скороговорки.

**Длина правится текстом раньше, чем темпом.** Если перевод заведомо не влезает
в слот, модель перевода просят переписать его короче (`shorten`). Сжатие
формулировкой не слышно, ускорение речи — слышно.

**Перевод видит диалог.** `mlx-chat` показывает модели соседние реплики, пол
говорящего, глоссарий и требуемую форму обращения. Это лечит ошибки уровня
«Oh you are?» → «Кто вы?», «I am not» → «Я не являюсь», «modeling» →
«моделирование», «хотел(а)» и скачки ты/вы между соседними репликами.

Цена — время. Замерено на M4 (F5 через torch MPS): `nfe_step: 8` даёт ×2.4
длительности речи, `nfe_step: 16` — ×4.9. Ролик с 8 минутами речи занимает
примерно 20 и 40 минут соответственно, плюс Demucs. Для скорости остаётся
`local-balanced`.

#### Что ещё изменилось во всех локальных маршрутах

- **Отказ модели не попадает в дорожку.** Если LLM вместо перевода отдаёт
  «Я не могу выполнить эту просьбу…» или разбор слова («это сленговое, нужен
  контекст»), реплика отбраковывается и переводится повторно по одной; ранее
  такой абзац озвучивался как реплика.
- **Каждая реплика переводится со своего языка.** Раньше на весь ролик брался
  один доминирующий язык, и чешские вставки в английском диалоге читались как
  английские.
- **Зацикливание распознавания сворачивается.** Повтор «Я собираюсь посмотреть
  на своё лицо» ×5 схлопывается в одну копию до перевода и озвучки.
- **Вокализации остаются оригиналом.** Чистые «Oh», «um ah um», «mm-hmm» не
  переводятся и не синтезируются: на их месте звучит исходный звук.
- **Говорящие определяются по всему файлу.** Вместо пореплечного F0 (который
  давал «30 мужских, 100 женских» на диалоге двух человек) реплики
  кластеризуются целиком по ролику, а роль голоса выбирается голосованием
  внутри кластера. Отключается через `speaker.enabled: false`.
- **Речь отделяется от фона** (`separation.enabled`, Demucs): распознавание
  перестаёт выдумывать текст на музыке, образцы голоса выходят чистыми, а фон
  в миксе играет целиком — приглушать его под репликами больше не нужно.

Если модель перевода отказывается переводить откровенные или грубые реплики,
укажите в `translation.model` модель без safety-фильтра: отказы дубляж
отбрасывает, и такие реплики останутся без озвучки.

Для выбора всех трёх локальных профилей один раз выполните
`uvt setup-mac-local --preset all`. При старте сервер без сети проверит каждый
вариант; отсутствующая модель будет отключена в панели до скачивания видео.

## Пакетный дубляж: файл, ссылка и браузер

```bash
uvt dub фильм.mp4 -p cloud-quality       # → фильм.dub.mkv + .srt + .json
uvt dub "https://youtube.com/watch?v=…" -p free
uvt dub файл.mp4 -p local --duck-db -18  # оригинал остаётся тихим фоном
```

Пакетный путь читает весь источник, распознаёт фразы с таймкодами, переводит их с контекстом и собирает отдельную дорожку. Он не перекодирует видеоряд без необходимости, а в MKV по умолчанию сохраняет оригинальную аудиодорожку. Это **voice-over с ducking**, не магическая изоляция и не покадровый lip-sync.

### Браузерная кнопка

```bash
uvt serve -p cloud       # облачный маршрут (OpenAI), localhost:8765
uvt serve -p free        # без платных API: локальные STT/перевод + Edge TTS через сеть
uvt serve-personal       # сразу Local/Free + GPT + ElevenLabs на портах 8765–8767
# uvt serve-personal --open-browser  # дополнительно открыть local dashboard
# либо: uvt serve -p local    # после настройки Piper и Ollama
```

Установите Tampermonkey и добавьте [browser/uvt.user.js](browser/uvt.user.js). Подробная инструкция — в [browser/README.md](browser/README.md).
После обновления `uvt.user.js` сохраните его в Tampermonkey
(или переустановите) и полностью перезагрузите открытую вкладку
YouTube: уже открытая страница иначе продолжит выполнять старую копию скрипта.

Корень Local/Free-маршрута, обычно
[`http://127.0.0.1:8765/`](http://127.0.0.1:8765/), — это dashboard для
мониторинга маршрутов, моделей и текущих задач, а также для настройки
следующих переводов. Вкладки **Free**, **GPT** и **ElevenLabs** в одной
панели управляют всеми тремя маршрутами.

Во Free можно выбрать языки, `local-fast`, `local-balanced` или
`local-quality`, а также мужской/женский или точный Piper-голос.
Для Mac M4 с 16 ГБ рекомендуется `local-balanced`; Fast быстрее,
а Quality требовательнее к памяти. В GPT отдельно выбираются модели
OpenAI для STT, перевода и TTS и голос OpenAI. В ElevenLabs
распознавание и перевод остаются на OpenAI, а для TTS можно выбрать
модель ElevenLabs и голос из аккаунта или ввести Voice ID. Проба
голоса до 240 символов для Free локальна; проба GPT/ElevenLabs
отправляет текст в облачный TTS и расходует API-квоту.

Кнопки **Сохранить**, **Отменить правки** и **Вернуть YAML по
умолчанию** работают отдельно для каждого маршрута. Сохранённые
значения применяются только к следующим новым задачам: уже запущенный
дубляж не меняется. Они хранятся в
`~/.config/uvt/server-settings.json`; путь можно переопределить через
`UVT_SETTINGS_PATH`. API-ключи в этот JSON не записываются; панель
получает только статус «задан/не задан».

Userscript 0.18 по умолчанию берёт модель, языки и голос из web-панели.
В панели на видео выберите **Свои настройки для этого видео**, если
нужно одноразово переопределить локальный профиль, языки или голос. Кнопка
**Вернуться к настройкам web-панели** снова включает серверные
значения. Громкости оригинала и перевода всегда остаются локальными
настройками браузера.

`--open-browser` по умолчанию выключен и предназначен для локального desktop-запуска.
UVT не пытается открыть вкладку на VPS/в headless-среде или при non-loopback `--host`.
При локальном запуске с `UVT_API_TOKEN` вкладка откроется и попросит его ввести.
В сети откройте HTTPS-адрес панели вручную и введите `UVT_API_TOKEN`
в форме входа: панель хранит его только в `sessionStorage` до закрытия
вкладки и добавляет к API-запросам как `X-UVT-Token`. За reverse proxy
задайте `UVT_FREE_PUBLIC_URL`, `UVT_GPT_PUBLIC_URL` и
`UVT_ELEVEN_PUBLIC_URL`, иначе межмаршрутные вкладки dashboard не будут
знать HTTPS-адреса трёх поддоменов. Готовый пример есть в
[инструкции VPS](docs/PERSONAL_DEPLOY.md).

Панель возле видео показывает реальные этапы `очередь → источник → STT → перевод → TTS → сборка`. Пока задача не завершена, видео продолжает играть оригинал. После готовности script подключает подготовленную дорожку и синхронизирует паузу, перемотку и скорость с видеоплеером.

## Live перевод системного звука

```bash
uvt devices                   # найти вход с отметкой 🔁
uvt run -p live                # live-перевод системного звука в консоли
# или: uvt gui -p live         # то же самое, но в desktop-интерфейсе
```

Для системного звука нужен **входной** виртуальный источник:

- macOS: `brew install blackhole-2ch` → Audio MIDI Setup → Multi-Output Device с динамиками и BlackHole;
- Windows: `wasapi-loopback` или VB-Cable/VoiceMeeter;
- Linux: выберите monitor-источник PipeWire/PulseAudio.

Не оставляйте «вход по умолчанию» без проверки: чаще всего это микрофон, а не Chrome/Zoom. GUI помечает потенциально виртуальные устройства `🔁` и объясняет выбранный источник.

Live-задержка складывается из окончания фразы (VAD), STT, перевода, TTS и вывода. UVT отбрасывает уже просроченные сегменты вместо бесконечного наращивания очереди: это полезнее для разговора, но означает, что при перегруженном железе часть реплик может быть пропущена. Смотрите p50, sync drift и счётчики drops в GUI/логах, а не только субъективное ощущение скорости.

В live-режиме доступны только два честных выхода:

- `subtitles` — текст без TTS;
- `voiceover` — перевод поверх исходного звука.

Старые CLI-значения `replace` и `dual` принимаются лишь для совместимости и приводятся к `voiceover`. Они не обещают удаления оригинальной речи или раздельного микширования.

## GUI

```bash
uvt gui -p free         # без платных API
uvt gui -p cloud-fast   # облачный маршрут с упором на минимальную задержку
```

В верхней части окна выбирается маршрут и сразу видно, какие данные остаются на устройстве и какие компоненты используют сеть. Вкладки разделяют Live и Batch:

- **Live:** вход/выход звука, оверлей, состояния Capture/VAD/STT/перевода/TTS/вывода, p50 и drops; ошибки остаются текстом в панели состояния.
- **Batch:** файл или URL, итоговый путь, уровень ducking и реальные этапы обработки. Отмены batch-работы пока нет — это явно отмечено в интерфейсе.

Оверлей не забирает фокус у звонка или видео, его можно перетащить, а правый/двойной клик временно скрывает до следующей реплики.

## Голоса, спикеры и точность

`voice: auto` — это выбор **тембра переводчика**, а не доказательство пола, личности или количества людей. F0/тембровые признаки могут ошибаться на шуме, музыке, детских голосах и при нескольких похожих голосах. UVT не должен использоваться для биометрических выводов.

Для live сессии speaker layer держит нейтральные идентификаторы (`speaker-1`, `speaker-2`, …), confidence и сопоставление `speaker_id → voice role`. Их можно переопределить в `speaker.voice_map`; это лучше, чем выдавать эвристику за точное «мужской/женский». Полная диаризация и клонирование голоса — отдельные будущие возможности, требующие оценки качества, лицензий и согласия говорящих.

## Архитектура и расширение

Каждый этап — независимый asyncio-сервис с очередями и ленивыми движками. Подробная схема, источники времени, budget задержки и plugin API — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Свой STT/переводчик/TTS/захват добавляется из [plugins/](plugins/README.md) без правки ядра.

## Ограничения и безопасность

- DRM-защищённые потоки (Netflix и т.п.) не поддерживаются.
- Качество зависит от модели, языка, шума, скорости речи и выбранного маршрута; не используйте результат там, где нужен сертифицированный перевод.
- Передавайте в cloud-профили только контент, на который у вас есть право и согласие для обработки выбранным провайдером.
- `uvt serve` слушает localhost, но localhost не делает сетевые движки локальными.
- Переводите только контент, к которому у вас есть законный доступ, и соблюдайте условия сайтов/API.

### Личный сервер: Free, GPT и ElevenLabs одновременно

Для Linux VPS есть профиль [`free-vps`](profiles/free-vps.yaml): он заменяет
Apple-only MLX Whisper на CPU `faster-whisper` и использует `qwen2.5:3b` через
Ollama. Один раз перед первым запуском скачайте локальную модель:

```bash
ollama pull qwen2.5:3b
```

После этого все три версии запускаются одной командой:

```bash
uvt serve-personal
```

Обёртка `bash scripts/serve-personal.sh` запускает ту же команду. На Linux по
умолчанию `free-vps` работает на `127.0.0.1:8765`, `cloud-fast` — на `127.0.0.1:8766`,
`cloud-eleven` — на `127.0.0.1:8767`. Userscript отправляет задачу только в
выбранный маршрут: получение исходного звука и batch-конвейер одинаковы, а
профиль определяет STT, перевод и финальную озвучку. Для VPS, HTTPS и токена
доступа следуйте [инструкции](docs/PERSONAL_DEPLOY.md).

На Mac с Apple Silicon `serve-personal` автоматически выбирает полностью
локальный `local-balanced`. Переменная в `.env` нужна только для явного
переопределения:

```bash
UVT_FREE_PROFILE=local-fast
```

На Linux/VPS оставьте `free-vps`. То же можно выбрать разово:
`uvt serve-personal --free-profile local-quality`.
Сохранённый выбор в web-панели имеет приоритет для следующих задач;
кнопка **Вернуть YAML по умолчанию** удаляет это переопределение.
