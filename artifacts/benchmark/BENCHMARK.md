# Реальные локальные замеры на M4 / 16 ГБ

Проверен установленный `local-balanced`: **Parakeet v3 → TranslateGemma 4B 4-bit → Piper**, английский → русский. Нейтральная запись встроенным macOS-голосом Samantha длится **13,970 с**. Полная команда завершилась за **36,96 с**; это **2,65 секунды работы на секунду исходника**, медленнее реального времени на данном коротком запуске.

| Измерение | Результат |
|---|---:|
| Распознавание, включая загрузку Parakeet | 7,2 с |
| Перевод, включая загрузку TranslateGemma | 26,3 с |
| Из этого загрузка TranslateGemma по времени логов | примерно 18,6 с |
| Генерация перевода после загрузки по времени логов | примерно 7,4 с |
| Синтез и подгонка голоса | 2,0 с |
| Первый готовый клип от старта Python | 35,406 с |
| Работа Python до сохранения результата | 35,889 с |
| Команда целиком, `/usr/bin/time -l` | 36,96 с |
| Итоговая дорожка | 15,352 с, 5 реплик |
| Peak memory footprint по macOS `time -l` | 4 871 442 488 байт ≈ 4,54 GiB |
| Peak RSS процесса | 1 186 922 496 байт ≈ 1,11 GiB |
| Peak MLX allocator | 2 764 520 201 байт ≈ 2,57 GiB |

Метрики памяти имеют разные определения и пересекаются: **их нельзя складывать**. Peak RSS сам по себе не отражает весь расход объединённой памяти на Metal.

Распознавание совпало с исходным текстом после нормализации регистра, пунктуации и записи времени `ten fifteen` / `10:15`. В русском переводе сохранены время встречи, бюджет, риски, два варианта и запрет отправки до согласования. Слово `draft` переведено менее точно как «этот вариант» вместо «черновик». Последняя озвученная реплика удлиняет итоговую дорожку примерно на 1,38 с.

Эвристика говорящих разделила один синтетический голос на два кластера; оба получили женский тембр, поэтому смены пола голоса в этом случае нет. Естественность звучания не оценивалась прослушиванием: приложен WAV для самостоятельного сравнения.

Это один короткий чистый синтетический пример в новом процессе, с загрузкой моделей. Результат не показывает скорость прогретого сервера, качество шумных диалогов, украинскую озвучку или производительность длинного видео. Первый клип появился почти в конце обработки — наличие прогрессивной выдачи само по себе не означает быстрый старт или live-перевод.

Из замера следует конкретная точка для последующего исследования: загрузка TranslateGemma заняла больше времени, чем генерация текста. Управление прогревом и освобождением моделей нужно оценивать с ограничением 16 ГБ и отдельным сравнением холодного и прогретого запуска; этот замер не доказывает ускорение от такого изменения.

Запуск был полностью автономным: HTTP-сервер не поднимался, скачивания моделей запрещены `allow_download=false`, `HF_HUB_OFFLINE=1` и `TRANSFORMERS_OFFLINE=1`; облачные запасные движки отсутствовали. Использовались уже установленные модели и pinned revisions профиля.

Артефакты: `source-en.txt`, `source-en.wav`, `offline-translation-ru.wav`, `offline-translation-ru.srt`, `offline-translation-ru.json`, подробный `offline-result-ru.json` и журналы `offline-process.log` / `offline-progress.log`.


## Повторная обработка в исходном проекте «голос»

В отдельном процессе выполнены **ровно два обычных последовательных**
`render_dub_track` с тем же `local-balanced` и тем же нейтральным исходником
13,970 с. Импорт проверен перед обработкой:
`/Users/teotim/Documents/голос/src/uvt/__init__.py`. Источник:
`/Users/teotim/Documents/голос/artifacts/benchmark/source-en.wav`.

| Измерение | Первый render | Повторный render |
|---|---:|---:|
| Весь render | 38,920 с | 20,127 с |
| Первый готовый клип | 37,393 с | 19,060 с |
| Распознавание, включая загрузку | 8,1 с | 3,7 с |
| Перевод, включая загрузку | 25,2 с | 13,8 с |
| Загрузка TranslateGemma по границам логов | ≈13,36 с | ≈6,15 с |
| Генерация перевода после загрузки | ≈11,27 с | ≈7,46 с |
| Озвучка и подгонка | 5,3 с | 2,3 с |
| Секунд работы на секунду исходника | 2,786 | 1,441 |
| Peak MLX allocator за render | ≈2,57 GiB | ≈2,57 GiB |

Повторный render завершился в **1,93 раза быстрее** первого, сократив время
на **48,3%**. Но даже он требует около 20,1 с на 14 с записи, а первый клип
появляется лишь через 19,1 с: этот результат не подтверждает перевод
в реальном времени. Основная оставшаяся задержка — перевод: 13,8 с из 20,1 с.

Модели работали с существующим порядком закрытия и повторной загрузки.
Логи подтверждают повторную загрузку Parakeet и TranslateGemma во втором
render. Улучшение нельзя приписывать постоянному хранению моделей в памяти:
повторный запуск использует прогретый Python и системные/библиотечные кэши,
а влияние нагрузки и температуры этим единственным сравнением не отделено.
Код движков и их политика загрузки не менялись.

Тексты распознавания и перевода всех пяти реплик совпали в обоих render.
Качество звучания в этом сравнении отдельно не оценивалось. Тот же пример
не заменяет тесты длинной записи, шумной речи или диалога нескольких людей.

Вся команда с двумя render заняла **61,83 с**. Общий пик процесса по
`time -l`: **5 261 119 952 байт ≈ 4,90 GiB memory footprint**; пик RSS —
**1 342 160 896 байт ≈ 1,25 GiB**. Это пики всего процесса с двумя render,
не независимые показатели каждого запуска. RSS и MLX allocator не складываются
с memory footprint.

`ensure_media_runtime()` подтвердил FFmpeg и применил существующую совместимую
библиотеку только к процессу. HTTP-сервисы не запускались; модели и голоса
не скачивались. Настройки `allow_download=false`, офлайн-флаги Hugging Face
и отсутствие облачных fallback проверены перед обоими render.

Подробности: `warm-comparison.json`, `warm-comparison-progress.log`,
`warm-comparison-process.log`. Новых прогонов после этого сравнения не выполнялось.
