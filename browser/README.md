# Кнопка UVT в браузере — пакетный дубляж

Аналог [voice-over-translation](https://github.com/ilyhalight/voice-over-translation),
но задачу готовит запущенный у вас UVT. Сам UVT может быть полностью локальным
(`local-fast`, `local-balanced`, `local-quality`) или использовать cloud-движки — маршрут явно выбирается
профилем, а не скрыт за кнопкой.

Как это работает: userscript вешает кнопку **UVT · перевести** на любой
`<video>` на странице. По нажатию адрес страницы (и прямая ссылка на поток,
если есть) уходит на локальный сервер `uvt serve`; тот скачивает звук,
распознаёт и переводит ролик, затем публикует готовые озвученные реплики
по таймкодам и собирает итоговую аудиодорожку. Скрипт проигрывает доступные
реплики синхронно с видео, а затем включает цельную дорожку. Он никогда не
меняет системную громкость, `volume`, `muted` или состояние воспроизведения
самого плеера до готовности дорожки. Там, где браузер безопасно даёт подключить
Web Audio (например, MSE/blob), оригинал приглушается только в фактических
окнах TTS; для остальных источников остаётся нетронутым, а перевод звучит
поверх. Это voice-over, а не изоляция исходного голоса. Пауза, перемотка и
скорость видео синхронизируются автоматически.

Это **подготовка видео по этапам, не live-перевод**. Первые реплики доступны
после распознавания, перевода и начала озвучки; время ожидания зависит от
видео и моделей. Для живого системного звука нужен отдельный режим `uvt run`
с настроенным аудиозахватом.

## Установка (один раз)

1. Расширение [Tampermonkey](https://www.tampermonkey.net/) в Chrome/Firefox/Edge.
2. Tampermonkey → «Создать новый скрипт» → вставьте содержимое
   [uvt.user.js](uvt.user.js) → Сохранить (⌘S).
3. На Apple Silicon установите сервер, yt-dlp и локальные движки:

   ```bash
   pip install -e ".[mac-local,server,web]"
   uvt setup-mac-local --preset balanced
   uvt setup-mac-local --preset balanced --check
   ```

Для M4 / 16 ГБ начните с `balanced`. Дополнительные `fast` и `quality`
устанавливайте по необходимости; `--preset all` скачивает весь базовый набор.
В списке можно выбрать только профили, установку которых подтвердил сервер.
Наличие файлов не означает, что модель уже загружена в память: панель
отдельно показывает её фактический статус.

При обновлении замените текст уже существующего Tampermonkey-скрипта целиком
и сохраните его — либо переустановите userscript из [uvt.user.js](uvt.user.js).
Убедитесь, что в шапке стоит `@version 0.18.0`, затем полностью
перезагрузите вкладку YouTube. Простое обновление файла в репозитории
не обновляет уже внедрённый код: без сохранения/переустановки и перезагрузки
открытая страница продолжит выполнять старую копию. Не создавайте вторую копию:
два активных UVT-скрипта нарисуют два набора кнопок.
Если клик по UVT вместо действия ставит YouTube на паузу, вкладка всё ещё
выполняет старую версию: для новой web-панели и исправленных кликов
нужна `0.18.0` или новее.

## Использование

```bash
cd ~/Documents/голос && source .venv/bin/activate
uvt serve-personal
# Free/Local: http://127.0.0.1:8765 (Mac: local-balanced по умолчанию)
# GPT:        http://127.0.0.1:8766 (OpenAI STT + GPT + OpenAI TTS)
# ElevenLabs: http://127.0.0.1:8767 (OpenAI STT + GPT + ElevenLabs TTS)
```

После запуска откройте
[`http://127.0.0.1:8765/`](http://127.0.0.1:8765/): это local dashboard со
статусами маршрутов, моделей и текущих задач, а также с полными
настройками Free/GPT/ElevenLabs. Автооткрытие по умолчанию выключено;
для локального desktop-запуска его можно явно включить:

```bash
uvt serve-personal --open-browser
```

UVT не пытается автоматически открыть dashboard на VPS/в headless-среде
или при non-loopback `--host`. При локальном запуске с `UVT_API_TOKEN` вкладка
откроется и dashboard покажет форму входа. Он будет хранить
введённый токен только в `sessionStorage` до закрытия вкладки. К API-запросам
он добавляется как `X-UVT-Token`. Для вкладок трёх маршрутов за
reverse proxy также задайте `UVT_FREE_PUBLIC_URL`, `UVT_GPT_PUBLIC_URL` и
`UVT_ELEVEN_PUBLIC_URL`, как показано в [инструкции VPS](../docs/PERSONAL_DEPLOY.md).

### Настройки по умолчанию в web-панели

Нажмите **Настроить** в строке маршрута или переключите вкладку **Free**,
**GPT** или **ElevenLabs**. Выбор в web-панели становится значением по
умолчанию для **следующей** новой задачи; уже запущенный перевод не меняется.

- **Free:** исходный/целевой язык, `local-fast`, `local-balanced` или
  `local-quality`, тембр и точный Piper-голос. Для Mac M4 / 16 ГБ
  рекомендуется **Сбалансированный**: Parakeet + TranslateGemma 4-bit +
  Piper. **Быстро** использует Parakeet + NLLB, **Качество** — Whisper
  large-v3-turbo + TranslateGemma. В готовом наборе: Ирина/Дмитрий для RU и
  Тетяна/Микита для UK.
- **GPT:** STT `gpt-4o-mini-transcribe`, `gpt-4o-transcribe` или `whisper-1`;
  перевод `gpt-4o-mini` или `gpt-4o`; TTS `tts-1`, `tts-1-hd` или
  `gpt-4o-mini-tts`. Список голосов фильтруется по выбранной TTS-модели;
  доступны `alloy`, `ash`, `coral`, `echo`, `fable`, `nova`, `onyx`, `sage`,
  `shimmer`, а для `gpt-4o-mini-tts` также `ballad`, `verse`, `marin` и `cedar`.
- **ElevenLabs:** те же варианты OpenAI STT/перевода; TTS
  `eleven_multilingual_v2`, `eleven_flash_v2_5` или `eleven_turbo_v2_5`.
  Dashboard показывает голоса из вашего ElevenLabs-аккаунта; можно
  также ввести точный Voice ID.

Нажмите **Сохранить** для записи, **Отменить правки** для отката формы или
**Вернуть YAML по умолчанию**, чтобы удалить сохранённое переопределение.
Настройки хранятся в `~/.config/uvt/server-settings.json`; для другого пути
задайте `UVT_SETTINGS_PATH`. `OPENAI_API_KEY`, `ELEVENLABS_API_KEY` и
`UVT_API_TOKEN` туда не записываются: панель показывает лишь статус ключа
провайдера.

Введите до 240 символов в **Пробе озвучки** и нажмите
**Прослушать**. Free/Piper создаёт пример локально; GPT и ElevenLabs
отправляют этот текст провайдеру и расходуют API-квоту. Аудио не
запускается само до явного нажатия.

Откройте страницу с видео → на плеере появится кнопка **UVT · перевести** →
нажмите. Панель покажет честные этапы `очередь → получение звука →
распознавание → перевод → озвучка → сборка дорожки`, позицию в очереди и
осторожную оценку времени, если сервер уже обработал задачи в этой сессии.
После готовности дорожка включается. При доступном Web Audio оригинал
приглушается только пока звучат реплики; иначе его громкость не меняется.
Кнопка меняется на **UVT · выключить**; повторное нажатие выключает только
дорожку UVT. Крестик отменяет подготовку.

Рядом с кнопкой **UVT · перевести** виден селектор **Free / GPT / ElevenLabs**:
выберите нужный результат до запуска. Выбор фиксируется для уже запущенной
задачи, поэтому опрос статуса, отмена и дорожка не попадут на другой сервер.
Кнопка **Настройки** открывает панель userscript. По умолчанию выбрано
**Web-панель сервера (по умолчанию)**: скрипт отправляет только
`settings_mode: "server"`, а модель, языки и голос берёт сервер. Изменение любого
поля включает **Свои настройки для этого видео**. В этом режиме можно задать:

- исходный и целевой язык;
- `Быстро` (Parakeet + NLLB), `Сбалансированно` (Parakeet + TranslateGemma) и
  `Качество` (Whisper + TranslateGemma);
- `Авто`, мужской или женский тембр, либо точный Piper-голос;
- Дмитрий/Ирина для русского и Микита/Тетяна для украинского;
- громкость оригинала и перевода;
- статус моделей и фактические STT/translation/TTS-движки;
- адрес каждого локального или сетевого маршрута.

Кнопка **Вернуть настройки сервера** удаляет ручное
переопределение для этого видео. Громкости оригинала и перевода всегда
хранятся в браузере и не входят в серверные настройки.

Точный голос имеет приоритет над режимом; смена режима сбрасывает точный выбор.
`Авто` — эвристика тембра для каждой реплики, а не биометрия и не определение личности.
Все выборы фиксируются в момент старта batch-задачи.

### Панель 0.18: локальные ресурсы и удобство

Панель стала шире, текст — 14 px, основные поля — 42 px. На узком экране
поля располагаются в один столбец; заголовок с крестиком остаётся видимым
при прокрутке. Tab перемещает фокус, Esc закрывает панель и возвращает фокус
на кнопку. Проба голоса и подключение с диагностикой свёрнуты по умолчанию.

Под выбором профиля видна рекомендация для M4 / 16 ГБ и отдельное
предупреждение для тяжёлого `local-natural`. Статус сервера показывает,
подтверждена ли локальная обработка, а состав движков находится
в **Подключение и диагностика**. Неподтверждённый профиль нельзя выбрать
до ответа сервера. В режиме настроек сервера поля показывают его текущие
языки и голос; изменение одного поля сохраняет остальные отображённые значения.

Кнопка **Файлы и переводы ↗** открывает `/workspace` текущего маршрута для
обработки скачанного видео. **Открыть web-панель** ведёт к настройкам сервера.
Во время задачи под кнопками видна полоска общей готовности; текущий этап
объявляется программой чтения экрана. Подробности этапа и готовых реплик
доступны в подсказке основной кнопки. Отмена останавливает также прогрессивную озвучку.

Для плееров с `blob:` userscript с момента загрузки страницы сохраняет до 64
найденных адресов медиа в памяти. Это помогает, когда ранний HLS/DASH-манифест
уже исчез из короткого списка сетевых ресурсов браузера. История ограничена
текущим iframe, в запрос передаётся до шести кандидатов; DRM не обходится.

### Проба голоса

В userscript раскройте **Прослушать локальные голоса**, введите до 240 символов и нажмите `▶ Мужской` или
`▶ Женский`: эта быстрая проба остаётся локальной и доступна для
Piper на маршруте Free. Кнопка `■ Стоп` отменяет ожидание или останавливает
воспроизведение. Для проб GPT/ElevenLabs и точного голоса используйте web-dashboard;
помните, что это расходует API-квоту. Результаты кратко кэшируются только в памяти
запущенного сервера.

Управление доступно с клавиатуры: обычные `button`/`label`, Tab и Enter/Space
работают нативно, а Esc закрывает настройки. При ошибке появится текстовая
панель с причиной, кнопками «Повторить» и «Закрыть». Если платный GPT/ElevenLabs
вернул HTTP 401/402/403/429, там же будет кнопка «Переключить на Free»: она выбирает
локальный маршрут и повторяет задачу из общего кэша исходного звука, без
повторного скачивания.

## Приватность и профиль

`uvt serve` слушает только localhost, но это **не гарантирует полностью
локальную обработку**: всё зависит от выбранных STT, перевода и TTS. Например,
Edge TTS, Google-free и OpenAI-совместимые URL вне `localhost` отправляют
данные внешнему сервису.

Коротко о готовых маршрутах:

- `local-fast`: Parakeet + NLLB + Piper на устройстве;
- `local-balanced`: Parakeet + TranslateGemma + Piper, рекомендуемый для M4/16 ГБ;
- `local-quality`: Whisper large-v3-turbo + TranslateGemma + Piper;
- `free`: локальные STT/перевод, но Edge TTS передаёт текст Microsoft;
- `cloud-fast` / `cloud-quality`: аудио и текст уходят выбранному cloud-провайдеру.
- `cloud-eleven`: распознавание и перевод выполняет OpenAI, озвучку — ElevenLabs.

Для бесплатного тарифа ElevenLabs профиль ограничивает burst до двух запросов
и выдерживает паузу между ними; временный HTTP 429 повторяется автоматически.
HTTP 402 означает, что API видит проблему квоты/биллинга (например, закончились
символы текущего периода), а не просто «нужна платная модель».

Список и подробности: `uvt profiles`.

Проверить активную конфигурацию без запуска перевода можно так:

```bash
curl http://127.0.0.1:8765/meta
```

Ответ содержит фактические движки, `data_leaves_device`, внешние компоненты и
явный признак `mode: "batch"`. Браузер передаёт серверу URL страницы/потока;
сервер скачивает исходный звук локально. Временные исходники удаляются после
задачи, а готовая M4A-дорожка хранится в локальном кэше до 7 дней.

## Перевод звучит по мере готовности

Начиная с версии скрипта 0.17.0 ждать всю дорожку не нужно. Озвученная реплика
готова окончательно — она уже уложена в свой тайминг, — поэтому сервер
публикует реплики по одной, а скрипт планирует каждую по её таймкоду. На
кнопке видно `реплик 12 · 40%`: столько реплик загружено и декодировано
в браузере. Это не число фактически услышанных реплик: видео может стоять
на паузе, находиться впереди готового перевода или ждать разрешения на звук.

Как это работает:

- сервер отдаёт каждую готовую реплику отдельным файлом (`/clip/<задача>/<n>.wav`)
  вместе с её положением в видео и длительностью;
- скрипт загружает реплики и планирует их через Web Audio по времени видео,
  а не по собственным часам, поэтому пауза, перемотка и изменение скорости
  учитываются;
- реплики не накладываются: если предыдущая ещё звучит, следующая начинается
  после неё — то же правило, что и в итоговой сборке дорожки;
- реплику, начало которой уже прошло больше чем на 0.4 с, скрипт пропускает,
  вместо того чтобы играть обрубок не к месту;
- оригинал приглушается только в окнах готовых реплик (там, где браузер
  разрешает Web Audio для этого плеера);
- как только сервер закончил, скрипт переключается на цельную дорожку: она
  надёжнее при перемотке в любое место.

Скорость относительно реального времени зависит от длины видео, плотности
речи, языков, выбранных моделей и свободной памяти. `local-balanced` — стартовый
вариант для M4 / 16 ГБ, без гарантии мгновенного начала. Если видео обогнало
готовые реплики, поставьте его на паузу или вернитесь назад. Тяжёлый
`local-natural` с разделением аудио и клонированием голоса лучше пробовать
на коротких файлах; считать его режимом для быстрых видеозвонков нельзя.

Полезно знать: аудиоконтекст создаётся в момент нажатия кнопки. Это
обязательное требование браузеров — созданный позже, он остался бы
приостановленным, и первые реплики не зазвучали бы.

## Если кнопка видна, но не нажимается

Исправлено в версии скрипта 0.16.0 — обновите `uvt.user.js` в Tampermonkey.

Причина была в том, где жил слой с кнопками. Раньше он вкладывался в контейнер
плеера, а там его перекрывают прозрачные оверлеи сайта и ограничивает чужой
контекст наложения: кнопка рисовалась, курсор менялся, но нажатие уходило
плееру. Плюс плееры вешают свои обработчики на контейнер и на `document` в
capture-фазе и глушат события до того, как они дойдут до цели.

Что изменилось:

- слой кнопок живёт в верхнем слое документа (`document.body`, а в полном
  экране — в текущем fullscreen-узле) и позиционируется по прямоугольнику
  видео, переезжая за ним при прокрутке, ресайзе и theatre-mode;
- нажатие обрабатывается в capture-фазе на `window`, то есть раньше любого
  обработчика сайта, и дальше не пропускается — поэтому клик по кнопке больше
  не ставит видео на паузу;
- скрипт стартует на `document-start`, чтобы этот перехват регистрировался
  раньше скриптов плеера;
- `pointer-events` у слоя и кнопок выставлены с `!important`: правила сайта их
  не обнулят;
- панель настроек тоже переехала в верхний слой — раньше в полном экране её
  не было видно.

Клавиатура работает как прежде: Enter и Space активируют кнопку под фокусом,
двойного срабатывания нет.

## Ограничения

- Распознавание и перевод требуют предварительной обработки; начало озвучки
  не мгновенное. Готовые реплики могут звучать до завершения всей задачи.
  Userscript не перехватывает звук вкладки или видеозвонка.
- Сайты с DRM (Netflix и т.п.) не поддерживаются: поток зашифрован.
- Готовый локальный набор Piper озвучивает RU и UK. Для другого целевого языка
  добавьте оба тембра в `tts.voice_models` или выберите GPT/ElevenLabs.
- Сначала сервер пробует поток, уже замеченный браузером, и лишь затем URL
  страницы через yt-dlp. Если сайт отдаёт только один цельный MP4 без отдельной
  аудиодорожки, весь файл всё равно нужно прочитать: ускорить это без другого
  доступного потока нельзя.
- Для localhost сервер по умолчанию не требует токен и любые локальные
  программы могут к нему обращаться. На удалённом VPS задайте `UVT_API_TOKEN`:
  API потребует `X-UVT-Token`, а готовая дорожка получит отдельный URL-токен.
  В userscript можно сохранить HTTPS-адрес каждого маршрута; токен задаётся в
  личной копии скрипта. Web-dashboard принимает тот же токен в форме входа и
  хранит его только в `sessionStorage` текущей вкладки. Полный пример reverse proxy и
  настройки userscript есть в
  [инструкции](../docs/PERSONAL_DEPLOY.md).

## Проверка интерфейса без моделей

`tests/userscript-fixture.html` имитирует локальный сервер и один видеоплеер.
В этой странице запросы к тестовым маршрутам не запускают реальные модели.
Проверка `tests/userscript-smoke.js` — функция для Playwright `page`: её можно
выполнить через browser `run_code` после открытия fixture. Она проверяет
серверные настройки, ручной запрос, восстановление defaults, недоступные
модели, ранний медиа-адрес, отмену, фокус, ширину 390 px и потерю соединения.
Это проверка UI и контракта запросов, не измерение скорости моделей или
совместимости всех видеосайтов.
