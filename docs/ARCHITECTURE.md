# Архитектура UVT

## Ключевые решения

| Решение | Почему |
| --- | --- |
| **Python 3.10+ / asyncio** | Вся ML-экосистема (faster-whisper, Silero, edge-tts, kokoro) — Python-first; тяжёлая математика выполняется в нативных библиотеках (CTranslate2, ONNX Runtime, PortAudio), поэтому GIL не мешает целям по задержке. При необходимости ядро можно переписать на Rust, не меняя контрактов сервисов. |
| **Сервисы + шина сообщений** (ТЗ §14) | Каждый этап — независимая asyncio-задача; связь только через топики (очереди с вытеснением старого). Ошибка одного сегмента или падение движка не роняет конвейер. |
| **Реестр движков + ленивые импорты** (ТЗ §15) | Ядро ставится без ML-зависимостей; движки объявляют себя декоратором `@register(kind, name)`, тяжёлые импорты — внутри `warmup()`. Пользовательские плагины — `.py`-файлы в `plugins/`, ядро не меняется. |
| **Единый OpenAI-совместимый переводчик** (ТЗ §4) | Один HTTP-клиент покрывает OpenAI, DeepSeek, Grok, Groq, OpenRouter, Ollama, LM Studio, llama.cpp и пользовательские endpoint — различаются только `base_url`/`model`/ключ. Нативные SDK (Gemini, Anthropic) добавляются как отдельные движки позже. |
| **16 кГц float32 моно — внутренний формат** | Требование Silero VAD и Whisper. CaptureService ресемплит нативную частоту устройства один раз (soxr), дальше формат стабилен. |
| **Silero VAD через onnxruntime, без PyTorch** | Модель ~2 МБ, CPU-инференс кадра — доли мс. Поддержаны v5 (`state[2,1,128]`) и v4 (`h/c`); формат определяется по именам входов графа. Резерв — энергетический VAD (ноль зависимостей). |

## Поток данных

```text
CaptureEngine (нативная частота) ──► CaptureService ──[audio: AudioChunk 16кГц]──► VADService
VADService ──[speech: SpeechSegment]──► STTService ──[transcript: Transcript]──► TranslationService
TranslationService ──[translation: Translation]──┬──► TTSService ──[tts: TtsAudio]──► OutputService
                                                 ├──► OverlayService (субтитры: лог / GUI-sink)
                                                 └──► HistoryService (srt/vtt/txt/json при остановке)
Все сервисы ──[status: ServiceStatus]──► GUI / диагностика
```

Правила шины:

- у топика несколько подписчиков, каждый со своей очередью (fan-out);
- очередь полна → вытесняется **самое старое** сообщение: конвейер реального
  времени должен отставать и догонять, а не копить бесконечный буфер;
- подписка происходит **до** `setup()` сервиса — пока Whisper греется,
  сегменты копятся, а не теряются;
- OutputService дополнительно пропускает сегменты старше `max_backlog_s`.

## Бюджет задержки (ТЗ §11, §18)

Полная задержка = `хвост VAD + STT + LLM + TTS + старт воспроизведения`.

| Стадия | ultra | balanced | accuracy |
| --- | --- | --- | --- |
| Хвост VAD (пауза-отсечка) | 300 мс | 500 мс | 800 мс |
| STT (small, GPU / CPU) | 80–300 мс / 0.3–1.5 с | ← | ← (large) |
| LLM (локальный 7B / облако) | 150–600 мс | ← | ← |
| TTS (edge, первые байты) | 150–400 мс | ← | ← |

Хвост VAD — принципиальный минимум закадрового перевода: реплика должна
закончиться, чтобы её перевести. Каждый сегмент несёт `Trace` с отметками
`speech_end → stt → translate → tts → play`; медианы по стадиям — это Debug
Console из ТЗ §20 (`--debug`, GUI, лог каждые 10 с).

## Захват по платформам

| ОС | Сейчас (v0.1) | Захват конкретного приложения (план v1.5) |
| --- | --- | --- |
| Windows | `wasapi-loopback` (PyAudioWPatch), любые кабели через `sounddevice` | Process Loopback API (`AUDIOCLIENT_ACTIVATION_TYPE_PROCESS_LOOPBACK`, Win10 20H1+) |
| macOS | `sounddevice` + BlackHole (Multi-Output Device) | CoreAudio process taps (macOS 14.4+, `CATapDescription`) |
| Linux | `sounddevice` + monitor-источники PulseAudio/PipeWire | PipeWire: линковка на конкретный узел приложения |

Вывод перевода симметричен: `output.device` может быть наушниками или вторым
виртуальным кабелем — так переведённая речь попадает в OBS/Discord/Zoom (ТЗ §10).

## Потоки и блокировки

- Аудио-callback'и PortAudio живут в своих потоках; в цикл событий данные
  попадают через `loop.call_soon_threadsafe` + неблокирующую очередь.
- Блокирующие вызовы (инференс Whisper, запись в OutputStream, загрузка
  моделей) обёрнуты в `asyncio.to_thread`.
- GUI: конвейер работает в фоновом потоке со своим asyncio-циклом; события
  доставляются Qt-сигналами (queued connection).

## Plugin API (ТЗ §15)

Контракты — в `uvt/interfaces.py`: `CaptureEngine.stream()`,
`VADEngine.prob(frame)`, `STTEngine.transcribe()`, `TranslationEngine.translate()`,
`TTSEngine.synthesize()`. Общие для всех: `warmup()` / `close()`; конфиг движка
приходит в `self.cfg`, неизвестные YAML-ключи секции разрешены и доступны как
атрибуты. Регистрация — `@register(kind, name)`; загрузка — из `plugin_dirs`.
Пример — в [plugins/README.md](../plugins/README.md).

## Офлайн-дубляж (uvt dub)

`uvt/dub.py` переиспользует те же движки и `Segmenter`, но без шины: файл
обрабатывается последовательно быстрее реального времени, поэтому завершение
детерминировано, а тайминги реплик — это позиции в файле. Сборка дорожки:
оригинал (48 кГц стерео) умножается на огибающую приглушения (duck, рампы
50 мс вокруг каждой реплики), поверх кладётся ресемплированный TTS; для видео
дорожка подмешивается через ffmpeg с `-c:v copy`. Ссылки скачиваются yt-dlp.
Живой конвейер и дубляж — два потребителя одной и той же логики нарезки
(`uvt/segmenter.py`), правки VAD автоматически действуют в обоих режимах.

## Осознанные упрощения v0.1 (и как их снимать)

- **Приглушение оригинала** (режимы replace/dual): требует per-app управления
  громкостью — pycaw (Windows), на macOS системного API нет (только через
  виртуальные устройства). Интерфейс `Ducker` появится в v1.5.
- **Потоковый LLM/TTS**: сейчас сегмент переводится и озвучивается целиком;
  стриминг сократит время до первого звука на 100–300 мс.
- **Захват конкретного приложения**: см. таблицу выше.
- **GUI/WASAPI не покрыты автотестами** — проверяются вручную на целевых ОС;
  ядро конвейера покрыто смоук-тестами на dummy-движках (`uvt run --profile demo`
  — та же проверка руками).
